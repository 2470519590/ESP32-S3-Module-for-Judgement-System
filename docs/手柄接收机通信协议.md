# ESP32 手柄接收机—底盘主控通信协议

本文档供底盘主控 STM32 使用，只定义 ESP32 UART0 输出的手柄控制帧。主控不需要解析 Wi-Fi、比赛服务器、L431PM 或 Xbox 原始 HID 报文；但 ESP32 会在内部依据 L431PM 的真实比赛状态决定本帧是否允许携带非零控制量。

## 1. 链路参数

| 项目 | 定义 |
|---|---|
| 发送端 | ESP32-S3 手柄接收机 |
| 接收端 | 底盘主控 STM32 |
| 接口 | UART0，ESP32 GPIO43 为 TX |
| 波特率 | 115200 |
| 格式 | 8N1，无硬件流控 |
| 方向 | ESP32 TX → 主控 RX |
| 周期 | 10 ms，约 100 Hz |

ESP32 与主控必须共地。主控接收到的是固定长度二进制帧，不是文本，不需要向 ESP32 回 ACK。

## 2. 14 字节控制帧

```c
typedef struct __attribute__((packed)) {
    uint8_t magic0;        // 0xC3
    uint8_t magic1;        // 0x3C
    uint8_t sequence;      // 0~255，溢出后回到 0
    uint8_t flags;         // bit0=BLE连接，bit1=HID有效
    int8_t  left_x;        // -127~127
    int8_t  left_y;        // -127~127
    int8_t  right_x;       // -127~127
    int8_t  right_y;       // -127~127
    uint8_t left_trigger;  // 0~255
    uint8_t right_trigger; // 0~255
    uint8_t dpad;
    uint8_t buttons_1;
    uint8_t buttons_2;
    uint8_t crc8;           // 前13字节 CRC-8/ATM
} controller_state_frame_t;
```

| 偏移 | 字段 |
|---:|---|
| 0 | `0xC3` |
| 1 | `0x3C` |
| 2 | `sequence` |
| 3 | `flags` |
| 4 | `left_x` |
| 5 | `left_y` |
| 6 | `right_x` |
| 7 | `right_y` |
| 8 | `left_trigger` |
| 9 | `right_trigger` |
| 10 | `dpad` |
| 11 | `buttons_1` |
| 12 | `buttons_2` |
| 13 | `crc8` |

摇杆值已经由 ESP32 转换为有符号 `-127~127`，且中心死区已处理：绝对值小于 8 时输出 0，主控不需要再次缩放。

## 3. flags

| 位 | 含义 |
|---:|---|
| bit0 | BLE 手柄已连接 |
| bit1 | 最近一次 HID 数据有效，数据年龄不超过 100 ms |
| bit2~7 | 保留，忽略 |

只有以下条件同时满足时，主控才允许执行运动和射击控制：

```c
(frame.flags & 0x03U) == 0x03U
```

否则应速度清零并禁止射击。

## 6. CRC-8/ATM

CRC 计算帧的前 13 字节，结果放入第 14 字节：

```text
poly=0x07, init=0x00, RefIn=false, RefOut=false, xorout=0x00
```

```c
uint8_t crc8_atm(const uint8_t *data, size_t length)
{
    uint8_t crc = 0;
    while (length-- != 0U) {
        crc ^= *data++;
        for (uint8_t bit = 0; bit < 8U; ++bit)
            crc = (crc & 0x80U) ?
                (uint8_t)((crc << 1U) ^ 0x07U) :
                (uint8_t)(crc << 1U);
    }
    return crc;
}
```

## 7. 主控接收与安全策略

1. 在接收缓冲区中搜索连续帧头 `C3 3C`。
2. 收满 14 字节后校验 CRC。
3. CRC 正确才更新控制状态。
4. CRC 错误时丢弃当前候选帧，继续搜索下一个帧头。
5. `sequence` 正常递增，允许 `255 → 0` 回绕；主控可用它统计丢帧。
6. 连续超过 150 ms 没有收到有效帧时，速度清零并禁止射击。

ESP32 即使手柄断开，或手柄仍连接但比赛状态失能，也会继续约 100 Hz 输出帧。手柄断开或 HID 超时时 `flags` 不满足有效条件；比赛状态失能时保留手柄真实连接/HID flags，但全部控制字段为 0。ESP32 在上电尚未收到 L431PM 状态、连续 300 ms 未收到 L431PM 状态、机器人死亡、比赛结束、判负或底盘断电时都会输出这种全零控制帧；主控仍必须按 flags 和控制字段执行安全策略。

## 8. 当前边界

- 手柄帧不包含机器人 ID、队伍、HP、比赛状态或比赛服务器信息。
- 扳机和按键只表示操作者意图，是否实际射击由底盘主控决定。
- 射击执行结果由主控通过其他链路通知 L431PM，不能通过本帧反馈。
- 当前 ESP32 已关闭 UART0 文本调试输出，UART0 应只连接底盘主控。
