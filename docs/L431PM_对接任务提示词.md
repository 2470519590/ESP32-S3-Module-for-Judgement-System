# 给 L431PM 开发者的对接任务提示词

请在 `E:\STM32_PROJ\l431_power_management\L431PM` 完成“L431PM ↔ ESP32-S3 比赛状态链路”。先检查现有改动，保留现有 LPUART1 ASCII 调试协议和现有 CAN 协议；不要烧录硬件。完成后构建验证，并报告修改文件、协议测试方式与尚未实现项。

## 目标与接线

- 使用 **USART2**，`115200, 8N1, 无硬件流控`。
- L431：PA2 = USART2 TX，PA3 = USART2 RX。
- ESP32：GPIO18 = UART1 RX，GPIO17 = UART1 TX；两端交叉连接并共地。
- 当前 `MX_USART2_UART_Init()` 已存在，但 `Bsp/bsp_uart.c`、中断、收发队列和 `Application/Protocol` 只绑定 LPUART1。请为 USART2 新增独立、非阻塞的中断收发/环形缓冲，不得破坏 LPUART1。

## 协议公共规则

- 固定长度二进制帧；小端序；CRC-8/ATM：poly `0x07`、init `0x00`、RefIn/RefOut=false、xorout `0x00`。
- 接收端以两字节帧头重同步；CRC 或长度错误仅丢弃当前候选帧。
- USART2 上电后自动开始发送状态帧，不等待订阅命令。

## L431 → ESP32：10 Hz 状态帧，11 字节

```c
typedef struct __attribute__((packed)) {
    uint8_t  magic0;        // 0xA5
    uint8_t  magic1;        // 0x5A
    uint8_t  sequence;      // 0..255
    uint8_t  flags;         // bit0: alive; bit1: shoot_enabled; bit2: power_on
    uint16_t hp;            // 小端
    uint16_t heat;          // 小端；现有 CAN 热量 0..45
    uint16_t power;         // 小端；100 ms 平均功率，整数 W
    uint8_t  crc8;          // 覆盖 magic0 至 power
} l431_status_frame_t;
```

`power` 可使用现有 `PowerReportSnapshot_t.chassis_power_avg_w` 并钳位到 `uint16_t`。`heat` 使用现有枪管 CAN 状态/查询的当前热量。ESP32 负责补充机器人 ID，不由 L431 发送。

`power_on=1` 表示当前底盘供电输出已打开，`0` 表示输出已关闭；必须直接来自 L431PM 的实际底盘开关状态，不能根据 HP、比赛状态或功率值推测。

## L431 → ESP32：异步事件，均为 4 字节

```text
攻击        B1 1B | sequence | crc8
受击        B2 2B | sequence | crc8
死亡        B3 3B | sequence | crc8
复活        B4 4B | sequence | crc8
允许射击    B5 5B | sequence | crc8
禁止射击    B6 6B | sequence | crc8
脱离战斗    B7 7B | sequence | crc8
```

- 枪管累计有效射击数增长且当前未战斗 → 进入战斗事件；最后一次有效射击后 800 ms 未再增长 → 脱离战斗事件。
- 装甲板 CAN 有效 HIT → 若当前存活，HP 减 20，并发受击事件。
- 比赛射击许可从禁止变允许 / 允许变禁止 → 分别发 B5 / B6。许可仅由比赛开始/结束、存活状态和第三张黄牌判负决定，不由电源通断电推导。
- 新事件不得在 UART ISR 中直接阻塞发送；进入小事件队列，由协议任务输出。
- ESP32 UART0 只向主控发送手柄控制，不会把 `shoot_enabled` 回传主控。L431 通过 LPUART1 向主控发送独立的 `FIRE=ON/OFF` 比赛许可；主控负责最终执行和互锁。USART2 的 B5/B6 只是给 ESP32/服务器的状态通知。

## L431 比赛状态机

- 上电默认：`hp=0`、`alive=0`、比赛结束。
- 装甲板有效受击：仅当 `alive=1` 时扣 20 HP；扣至 0 时立即 `alive=0`、发死亡事件，并开始 5 秒计时。
- 正常复活：计时结束后设 `hp=300`、`alive=1`，发复活事件。
- 服务器设置 HP 是管理员覆盖：设正数时若死亡，立即复活并取消计时；设 0 时立即死亡并启动 5 秒计时。
- 比赛开始时 L431PM 自行设置 `HP=300、alive=1`，清除本场黄牌和判负状态；比赛结束停止比赛业务。HP、存活、复活、黄牌和判负均由 L431PM 维护，ESP32 不实现假状态。

## ESP32 → L431：服务器命令与回执

ESP32 会发送以下独立命令。`transaction_id` 是小端 `uint32_t`；L431 收到重复事务不得重复执行，只回相同结果。命令处理应在 200 ms 内完成；`result`：`0=成功`、`1=不允许`、`2=失败`。

```text
比赛开始：C1 1C | transaction_id[4] | crc8                    （7 字节）
比赛结束：C2 2C | transaction_id[4] | crc8                    （7 字节）
设置 HP ：C3 3C | transaction_id[4] | hp[2] | crc8            （9 字节）

开始回执：D1 1D | transaction_id[4] | result | crc8           （8 字节）
结束回执：D2 2D | transaction_id[4] | result | crc8           （8 字节）
设血回执：D3 3D | transaction_id[4] | result | crc8           （8 字节）

强制断电：C5 5C | transaction_id[4] | crc8                    （7 字节）
断电回执：D5 5D | transaction_id[4] | result | crc8           （8 字节）
请求通电：C6 6C | transaction_id[4] | crc8                    （7 字节）
通电回执：D6 6D | transaction_id[4] | result | crc8           （8 字节）
```

`SET_HP` 仅接受 `0..300`，用于管理员直接覆盖血量。比赛服务器正常开局发送 `GAME_START`；L431PM 收到后自行设置 `HP=300、alive=1`，清除本场黄牌和判负状态，再返回成功回执。服务器不需要先发送 `SET_HP=300`。

新增服务器处罚命令：`C4 4C | transaction_id[4] | crc8`（7 字节），回执为 `D4 4D | transaction_id[4] | result | crc8`（8 字节）。比赛进行中每收到一次该命令，L431PM 自己累计一次黄牌：第 1、2 次各扣 50 HP，第 3 次直接判负且不再自动复活；命令重复事务不得重复处罚。ESP32 只转发并等待回执。

`C5` 只关闭底盘/弹道供电输出，不关闭 L431PM；`C6` 调用 L431PM 的安全通电接口，保护条件不满足时返回失败。两者执行后的结果必须反映在后续 10 Hz 状态帧的 `power_on` 位中。

## 实现约束与验收

- 现有 LPUART1 ASCII 命令、CAN 枚举、装甲板/枪管协议不得回退或删除。
- USART2 IRQ、RX/TX 缓冲、状态发送和事件队列必须与 LPUART1 独立。
- 验收至少包括：USART2 状态帧 CRC/长度和 `power_on`；所有命令和重复事务回执；受击扣血、死亡、5 秒复活；枪管攻击事件；`FIRE` 许可事件；通电/断电后状态位变化；LPUART1 原有 `PING` 仍正常。
- 不要烧录或修改硬件配置以外的无关文件。
