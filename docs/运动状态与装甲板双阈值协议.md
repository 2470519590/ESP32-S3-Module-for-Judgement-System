# 运动状态与装甲板双阈值协议

## 1. 升级边界

只更新 ESP32、L431PM 和服务器。不修改、不重新烧录装甲板固件或装甲板
CAN-Bootloader，不新增装甲板命令。装甲板运行时 P04 写入按不保存 Flash
处理，所有下发都使用既有参数 `0x04`。

链路为：手柄 -> ESP32 判断动静 -> UART 通知 L431 -> L431 选择阈值 ->
CAN P04 写入装甲板。服务器可以修改每台机器人四个 NodeID 各自的静止、
运动阈值，共 4 x 2 个参数；配置的权威副本保存于 L431 Flash。

动静状态切换不写 L431 Flash。L431 无需服务器持续在线即可切换阈值；
ESP32 无需 L431 在线即可继续按原规则发送底盘手柄控制。

## 2. 动静判断

`motion=0` 未知，`1` 静止，`2` 运动。这是手柄输出意图，不是速度计测量。

- 使用现有左摇杆转换和死区；转换后左 X 或左 Y 非零立即进入运动。
- `report[13] & 0x40` 为 LB，`report[13] & 0x80` 为 RB，任一有效立即进入运动。
- 上述输入全部释放满 300 ms 后进入静止，右摇杆、扳机及其他按键不触发运动。
- 死亡或服务器软断电阻止控制输出时，按无运动输出处理，保留 300 ms 延迟。
- 手柄断连或报告超过 100 ms 未更新时进入未知。
- L431 连续 1000 ms 未收到合法运动通知时进入未知；未知使用运动阈值。

ESP32 的 100 Hz 底盘控制帧格式不变。运动 UART 通知由独立任务发送，
不在底盘任务里等待 L431 ACK、服务器 ACK 或 Flash 保存。

## 3. UDP V2

保留 `version=2`，既有帧布局不变。所有多字节整数小端，UDP 不额外加 CRC。
服务器使用既有绑定端口（默认 5005）发送到 ESP32 下行端口（默认 5006）。

### 运动上报 0x0E

ESP32 -> 服务器，7 字节：

```text
54 52 02 0E robot_id motion sequence
```

状态变化后在下一次网络发送循环上报，循环约 100 ms；状态不变时每
500 ms 重发当前快照以恢复丢包，无 ACK。sequence 为 8 位递增计数，
允许回绕及 ESP32 重启后归零。服务器超过 2 秒未见新快照显示 UNKNOWN。
没有 L431 连接时仍可上报；robot_id=0 未分配时不发送机器人业务帧。

### 设置单板单档阈值 0x8A

服务器 -> ESP32，15 字节：

```text
54 52 02 8A robot_id node profile value[4] transaction_id[4]
```

node=1..4，profile=0 静止、1 运动；value 为 1000..67108864 的无符号
整数，且每块板必须满足静止阈值 <= 运动阈值。先提高运动值再提高静止值；
先降低静止值再降低运动值，避免中间配置违反约束。

仅单播到非零机器人 ID。ESP32 转发 C9，等待 L431 D9 后回既有 F0：

```text
54 52 02 F0 8A transaction_id[4] result
```

result=0：L431 已保存配置，不等于装甲板已应用；1：参数拒绝；
2：暂时失败（链路不可用、队列满、Flash 保存失败或 UART ACK 超时）。
失败可使用同一事务号重试；成功/拒绝复用既有事务去重机制。
CLI 每 1 秒重试，包含首次共最多 3 次，之后显示 TIMEOUT。
同一机器人须等待上一条配置命令结束，再修改下一项。

### L431 阈值快照 0x0F

ESP32 -> 服务器，22 字节：

```text
54 52 02 0F robot_id node motion applied_mask failed_mask storage_status
still[4] moving[4] applied[4]
```

每个网络循环轮换发送一个 NodeID，通常每块板约 400 ms 一次。
ESP32 只转发最近 700 ms 内收到的该槽 UART 快照，避免断链后持续刷新旧数据。
服务器超过 2 秒没有该槽快照，显示 UNKNOWN。

| 字段 | 含义 |
|---|---|
| still / moving | L431 当前保存或默认的两档配置 |
| applied | 该槽最后确认的有效值；0 表示无有效确认 |
| applied_mask | bit0..3 对应 NodeID 1..4，置位表示已 ACK 的值等于当前目标值 |
| failed_mask | bit0..3 对应重试失败槽；后台仍会再次尝试 |
| storage_status | 0=使用默认配置；1=配置已保存；2=最近一次保存失败，继续使用旧配置 |

只有 applied_mask 对应位置位才显示 APPLIED。未接板不妨碍保存配置，
但不能因此显示 APPLIED。快照中的 motion 是 L431 实际选择的状态，
0x0E 的 motion 是 ESP32 判断的状态，两者用于区分 UART 断链。

## 4. ESP32 与 L431 UART

沿用 115200、8N1 和 CRC-8/ATM（poly=0x07、init=0、xorout=0）。
CRC 覆盖除末尾 CRC 字节外的整帧。

| 方向 | 帧 | 长度 |
|---|---|---:|
| ESP32 -> L431 | `CA AC motion sequence CRC` | 5 |
| ESP32 -> L431 | `C9 9C transaction_id[4] node profile value[4] CRC` | 13 |
| L431 -> ESP32 | `D9 9D transaction_id[4] result CRC` | 8 |
| L431 -> ESP32 | `A6 6A sequence motion applied_mask failed_mask storage_status node still[4] moving[4] applied[4] CRC` | 21 |

CA 状态变化即发送，未变化时每 250 ms 重发，无 ACK；心跳仅更新动静
有效期，不触发重复 CAN 写入。A6 每 100 ms 轮换一个槽，四槽约 400 ms。
C9 成功仅表示配置存入 L431；CAN 下发由独立状态机异步执行。

## 5. 既有 CAN P04

使用标准帧、DLC=8，NodeID 1..4 的写入 ID 为 `0x13B/0x14B/0x15B/0x16B`，
ACK ID 为 `0x13C/0x14C/0x15C/0x16C`。

```text
写入：04 value_le32 00 sequence 00
回执：04 result applied_value_le32 sequence 00
```

L431 同时只等待一块板，校验 NodeID、参数号、sequence、result 和回显值。
100 ms 未获正确 ACK 则重试，每轮最多 3 次，失败后等待 1000 ms 再尝试。
成功后停止高频重试；由于运行时 P04 不保存在装甲板 Flash，L431 每块板
约每 2 秒低频补发一次，避免装甲板无上报的瞬时复位丢失阈值。目标值改变、
装甲板重新分配、UID 改变、离线后恢复或收到装甲板启动/复位帧时立即重新应用。
若运动与静止阈值相等，状态切换无需重复写入。

原有“上电统一写 700000”的发送器由此状态机替换，不存在两个发送器
相互覆盖。首次没有保存配置时，静止默认 700000，运动/未知默认 1000000。
配置按 NodeID 槽保存，不按物理方位或 UID 保存；换板占用同槽时继承该槽配置。

## 6. L431 保存与操作

L431 链接区域缩至 252 KiB，末尾 `0x0803F000..0x0803FFFF` 两页用作
配置日志，CRC 校验并最后写提交标志。仅修改配置时写入，重复相同值
不追加记录；轮换页时保留上一份已提交配置。动静切换不写 Flash。
普通断电应从最新有效记录恢复；全片擦除或擦除该区域会清除配置。
装甲板断电后，由 L431 在重新上线时补发，不依赖装甲板保存。

CLI 示例，机器人 2、NodeID 1：

```text
armor_thr 2 1 moving 1000000
armor_thr 2 1 still 700000
armor_thr_show 2
```

每次等待该事务 SAVED 或失败后再输入下一条。SAVED 之后通过
`armor_thr_show` 检查 CAN 是否 APPLIED；四块板分别使用 node=1..4。
CLI 从 L431 快照恢复参数，不在电脑另存一份权威配置。

联调顺序：先确认静止值 APPLIED，再单独测试左摇杆、LB、RB；释放
300 ms 后检查低阈值恢复；拔掉手柄检查 UNKNOWN/高阈值；最后分别重启
ESP32、装甲板及整车检查恢复。以上是验收步骤，不表示已经实机验证。
